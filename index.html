디스코드 챗봇 프로젝트
주요 진행 상황

본 발표에서는 디스코드 챗봇의 핵심 데이터 연동 방식 개선, 서버 아키텍처 환경 변화, 그리고 지속 가능한 서비스를 위한 단계별 개발 로드맵을 순서대로 공유합니다.

공공데이터 API 전환 완료

더미 데이터를 사용했던 기존과 달리, 국토교통부(TAGO) 표준 Open API 파이프라인으로 교체하여 실시간 데이터를 기반으로 응답할 수 있게 되었습니다.

/버스 명령어

ArvlInfoInqireService
  • 511번 버스 양방향 실시간 안내: 주안역환승정류장 및 정석항공과학고 정류장의 도착 예정 시간(분) 제공
  • 차량번호 교차 추정 알고리즘: 도착 정보와 노선 위치 GPS API 데이터를 교차 검증하여 예상 운행 차량 번호 매칭

/지하철 명령어

SubwayInfoService
  • 인천2호선 맞춤 연동: 마전역(운연 방면) 및 주안역(검단오류 방면) 등 주요 이용 노선 정보제공
  • 시간표 기반 남은 시간 계산: 정시성이 높은 시간표 데이터를 파싱하여 현재 시간 기준 "N분 후 출발" 자동 계산
  • 인증키 통일: 버스 API와 동일한 TAGO 통합 키를 사용해 별도 발급 없는 효율적 구조

서버 인프라: Oracle Cloud 24시간 무중단 환경 구축

지난 시연 방식 (Before)

개인 노트북 로컬 실행

노트북에서 파이썬 코드를 직접 실행하여 시연 진행. 노트북 덮개를 닫거나 절전 모드 진입 시 봇이 즉시 종료되며, 네트워크 환경 변화에 매우 취약한 단점 존재.

현재 구축 방식 (After)

Oracle Cloud를 통한 상시 가동

오라클 클라우드 우분투(Ubuntu 22.04 LTS) 인스턴스 구축 완료. 개인 PC를 꺼도 24시간 365일 디스코드 채널에서 끊김 없는 서비스 제공 가능.

클라우드 인프라 세부 구성 요소

systemd 데몬 프로세스

`chatbot.service` 등록을 통해 서버 재부팅 및 봇 비정상 종료 시 5초 내 자동 재시작 구현

KST (Asia/Seoul) 동기화

서버 타임존을 한국 시간으로 고정하여 버스/지하철 시간표 파싱 및 시간 계산 오류 원천 차단

VNIC 및 보안망 구성

오라클 VNIC 설정을 통한 고정 Public IP 바인딩 및 독립된 보안 그룹 구성을 통한 안전한 통신

향후 발전 목표

01

시간표 데이터베이스 연동 및 CRUD

기존 고정 `timetable.json` 방식에서 데이터베이스 연동 방식으로 전환하여, 사용자가 직접 슬래시 명령어로 수업을 추가/수정/삭제(CRUD)할 수 있도록 구현

02

교통 정보 커스텀 즐겨찾기

511번 버스 외에 학생 개인별 자주 이용하는 버스 정류장 및 지하철역을 개인 DB에 등록하고 관리할 수 있는 사용자 맞춤형 조회 기능 제공

03

학생 맞춤형 학점 계산기 추가

수강 과목별 학점과 성적을 입력 받아 평점, 졸업에 필요한 전공 및 교양 학점 등에 대한 정보를 제공하는 기능 개발
