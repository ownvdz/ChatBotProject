프로젝트 진행 상황 및
웹 서비스 전환 & /길찾기 핵심 로직

디스코드 봇의 위치 수집 한계를 극복하기 위한 웹 서비스 전환 과정과, ODsay 및 국토교통부(TAGO) 실시간 공공 API 교차 매칭 기술 현황을 정리한 발표 자료입니다.

1. 프로젝트 진행 상황 & 웹 전환 배경

웹 서비스 전환 핵심 계기 (Key Driver) Browser Geolocation

"사용자의 실시간 현재 위치 수집 한계 극복"

길찾기 서비스의 핵심은 '사용자의 현재 위치를 출발지로 바로 자동 설정'하는 편리함에 있습니다. 그러나 디스코드 봇 환경에서는 모바일/PC 사용자의 실시간 GPS 좌표를 수신하는 기능이 제한되어 있어 매번 정류장명이나 주소를 텍스트로 직접 입력해야 하는 큰 불편함이 존재했습니다.

이를 해결하기 위해 웹 브라우저의 Geolocation API를 활용하여 원클릭으로 현재 위치를 자동 파악하고 즉시 경로를 탐색할 수 있는 웹 서비스 환경으로 전환을 추진하게 되었습니다.

단일 API 한계 (Problem)

경로 엔진과 실시간 데이터의 불일치

경로 탐색 전문 API(ODsay)는 최적 경로 수립은 뛰어난 반면, 특정 버스 노선이나 지하철의 실시간 남은 시간 데이터 정확도가 저하되는 한계가 존재함.

하이브리드 해결책 (Solution)

ODsay + TAGO 공공 API 교차 매칭

ODsay의 경로 검색 능력과 국토교통부(TAGO) 실시간 수집 데이터를 결합하여 "최적의 환승 경로 + 정확한 실시간 남은 시간"을 동시 제공.

2. 전체 작동 프로세스 (4-Step Workflow)

01

좌표 변환 & 위치 획득

Geolocation / Station Coords

웹 브라우저 GPS 좌표 또는 검색 텍스트를 ODsay `searchStation` API로 WGS84 좌표(X, Y) 변환

02

최적 경로 탐색

odsay_search_path()

ODsay `searchPubTransPathT` API로 소요시간, 요금, 환승 횟수 및 세부 경로 구간(`subPath`) 추출

03

실시간 데이터 결합

TAGO API Cross-Match

구간별 매칭 수행. 버스 실시간 도착 정보 및 지하철 운행 시간표 연동 계산

04

웹 UI 동적 렌더링

JSON Response & Web UI

백엔드 API에서 가공된 구조화 JSON 데이터를 받아 웹 프론트엔드에서 직관적인 UI로 출력

3. 구간별 세부 데이터 결합 로직

🚶 도보 구간

trafficType == 3
  • 이동 거리(m) 단위를 가독성 높게 파싱
  • 구간별 예상 소요 시간 요약 표기

🚌 버스 구간

trafficType == 2
  • TAGO 노선 ID 조회: 버스 번호 기반 TAGO route_id 검색
  • GPS 정류장 매칭: 반경 150m/60m 좌표 비교 및 정류장 순번(nodeord) 검증으로 진행방향 선별
  • 실시간 정보 출력: 도착 예정 분(min) 및 남은 정류장 수 표기

🚇 지하철 구간

trafficType == 1
  • 시간표 연동: 요일별(평일/토/일) 고정 시간표 파싱 및 현재 시각 기준 계산
  • 진행 방면 추정: ODsay의 way 정보와 종점역명을 비교하여 도착 열차 매칭
  • 출발 시각 안내: 가장 가까운 다음 열차 시각(HH:MM) 및 남은 시간 표기

4. 기술적 핵심 해결 포인트 (Highlights)

이종 API 불일치 해결

정류장 이름 + GPS 좌표 하버사인(Haversine) 거리 계산 + 노선 정류장 순번 교차 검증 알고리즘으로 ODsay-TAGO간 ID 불일치 완벽 해소

캐싱을 통한 응답 속도 향상

변동성이 적은 버스 노선 정류장 데이터(24시간 TTL) 및 실시간 도착 정보(15초 TTL) 메모리 캐싱으로 API 호출 트래픽 절감

예외 처리 및 Fallback 시스템

주말 지하철 운행 데이터 공백 발생 시, 자동으로 평일 시간표 데이터 기반 안내 문구로 우회 출력하는 데이터 안정화 탑재

5. 디스코드 봇 vs 웹 서비스 비교 및 향후 계획

기존 (디스코드 봇)
  • 출발지 설정: 사용자 현재 GPS 수신 불가 (텍스트 직접 입력 필수)
  • 접근성: 디스코드 앱 설치 및 서버 입장 필요
  • UI 표현력: 단순 Embed 메시지 형태에 국한
개선 (웹 서비스 전환 후)
  • 출발지 설정: 클릭 한 번으로 Browser Geolocation GPS 수신
  • 접근성: 별도 설치 없이 URL 접속만으로 바로 이용
  • UI 표현력: 동적 컴포넌트, 모바일 최적화 웹 UI

향후 고도화 계획 (Roadmap)

지도 SDK 연동

카카오/네이버 지도 SDK를 도입하여 경로 선형 시각화 기능 추가

자주 가는 경로 저장

사용자별 등하교 자주 이용하는 노선 및 정류장 즐겨찾기 제공

PWA 앱화

모바일 홈 화면 추가 및 실시간 대중교통 도착 Push 알림 지원
