디스코드 봇 /길찾기
하이브리드 경로 탐색 로직

ODsay 경로 탐색 API와 국토교통부(TAGO) 실시간 공공 API를 교차 매칭하여, 최적 이동 경로와 실시간 버스·지하철 도착 정보를 동시에 제공하는 시스템 분석 자료입니다.

1. 핵심 개요 (Key Concept)

기존 문제점 (Problem)

단일 API 사용 시의 한계

경로 탐색 전문 API(ODsay)는 최적 경로 수립 능력은 우수하지만, 특정 지역 및 지방 노선의 실시간 도착 데이터 제공이 부족하거나 불확실한 한계가 존재함.

구축한 해결책 (Solution)

하이브리드(Hybrid) 교차 매칭 시스템

ODsay API의 경로 엔진과 국토교통부 TAGO 공공 API의 실시간 수집 데이터를 실시간으로 교차 결합하여 "최적 경로 + 정확한 실시간 남은 시간"을 일률 제공.

2. 전체 작동 프로세스 (4-Step Workflow)

01

좌표 변환

resolve_station_coords()

입력받은 출발지/목적지 텍스트를 ODsay `searchStation` API를 통해 WGS84 GPS 좌표(X, Y)로 변환

02

최적 경로 탐색

odsay_search_path()

ODsay `searchPubTransPathT` API로 총 소요시간, 요금, 환승 횟수 및 세부 경로 구간(`subPath`) 추출

03

실시간 데이터 결합

TAGO API Cross-Match

도보/버스/지하철 구간별 매칭 수행. 버스 실시간 도착 및 지하철 시간표 연동 계산

04

Embed 응답 출력

Discord Embed Message

요약 정보와 구간별 이동 가이드, 실시간 남은 시간 문구(`realtime_note`)를 조합하여 디스코드 전송

3. 구간별 세부 데이터 결합 로직

🚶 도보 구간

trafficType == 3
  • 이동 거리(m) 단위를 가독성 높게 파싱
  • 구간별 예상 소요 시간 요약 표기

🚌 버스 구간

trafficType == 2
  • TAGO 노선 ID 조회: 버스 번호 기반 TAGO route_id 검색
  • GPS 정류장 매칭: 반경 150m/60m 좌표 비교 및 정류장 순번(nodeord) 검증으로 올바른 진행방향 선별
  • 실시간 정보 출력: 도착 예정 분(min) 및 남은 정류장 수 표기

🚇 지하철 구간

trafficType == 1
  • 시간표 연동: 요일별(평일/토/일) 고정 시간표 파싱 및 현재 시각 기준 계산
  • 진행 방면 추정: ODsay의 way 정보와 종점역명을 비교하여 도착 열차 매칭
  • 출발 시각 안내: 가장 가까운 다음 열차 시각(HH:MM) 및 남은 시간 표기

4. 기술적 핵심 해결 포인트 (Highlights)

이종 API 불일치 해결

정류장 이름 + GPS 좌표 하버사인(Haversine) 거리 계산 + 노선 정류장 순번 교차 검증 알고리즘으로 ODsay-TAGO간 ID 불일치 완전 해결

캐싱(Caching)을 통한 응답 속도 향상

변동성이 적은 버스 노선 정류장 데이터(24시간 TTL) 및 실시간 도착 정보(15초 TTL) 메모리 캐싱으로 API 호출 최소화

예외 처리 및 Fallback 시스템

주말 지하철 운행 데이터 공백 발생 시, 자동으로 평일 시간표 데이터 기반 안내 문구를 전환하여 출력하는 안정화 로직 탑재

5. 🎤 1분 발표용 요약 스크립트

발표 스크립트 (Speech Script)
"저희 챗봇의 /길찾기 기능은 단순히 길만 찾아주는 것에 그치지 않고, '경로 탐색 API'와 '국토교통부 실시간 공공 API'를 결합한 하이브리드 로직으로 구현되었습니다.

ODsay API를 이용해 최적의 환승 경로를 탐색한 뒤, 각 버스 및 지하철 구간마다 국토교통부 TAGO API를 통해 실시간 버스 도착 시간과 지하철 다음 열차 시각을 실시간으로 가져옵니다.

이 과정에서 발생할 수 있는 이종 API 간 ID 불일치 문제는 GPS 좌표 거리 계산과 노선 순번 검증 알고리즘을 통해 해결했으며, 캐싱 로직을 적용해 신속하고 정확한 대중교통 경로 안내를 제공합니다."
