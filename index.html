프로젝트 진행 상황 및
웹 서비스 전환 & 길찾기 핵심 로직

ODsay(경로 탐색)와 국토교통부(TAGO) 공공 API(실시간 수집 데이터)를 결합한 길찾기 기능과, 디스코드 봇 환경의 한계를 극복하기 위해 진행한 웹 서비스 전환 과정을 정리한 발표 자료입니다.

1. 길찾기 기능의 핵심 — 서로 다른 API의 결합

왜 두 API를 함께 쓰는가

"실시간 수집은 강하지만, 경로 탐색은 할 수 없는 공공 API"

국토교통부(TAGO) 공공 API는 버스 도착 예정 시간, 버스 실시간 위치, 지하철 고정 시간표 등 현장 데이터를 수집·제공하는 데는 훌륭하지만, "출발지에서 도착지까지 어떤 노선을 타고 어디서 환승해야 하는지" 계산해주는 경로 탐색(길찾기) 기능 자체가 없습니다.

그래서 경로 탐색에 특화된 ODsay API로 최적 대중교통 경로(환승 순서·소요시간·요금)를 먼저 계산하고, 그 경로의 각 구간(버스/지하철)에 TAGO의 실시간 데이터를 매칭해 덧붙이는 방식으로 두 API를 결합했습니다.

TAGO 단독 사용 시 한계

경로 계산 기능 부재

정류장/역 단위 실시간 정보는 정확하지만, "어디서 타고 몇 번 환승해야 하는지"를 계산해주는 경로 탐색 엔진이 없어 길찾기 서비스로는 사용할 수 없음.

ODsay + TAGO 결합

최적 경로 + 정확한 실시간 정보

ODsay의 경로 탐색 능력으로 "최적 환승 경로"를, TAGO 실시간 데이터로 "지금 몇 분 후 도착하는지"를 동시에 제공.

2. 길찾기 작동 로직

STEP 1

위치 확정

이름 검색 또는 GPS 좌표로
출발·도착지를 동시에 확정

STEP 2

경로 탐색

ODsay가 최적 경로의
환승 구간(도보·버스·지하철)을 계산

CORE STEP 3

실시간 교차 매칭

구간마다 TAGO 실시간 데이터를
병렬로 매칭 (12초 내 응답 없으면 요약만 유지)

STEP 4

화면 출력

구조화된 JSON을 반환하면
프론트엔드가 보기 좋게 렌더링

3. 구간별 세부 매칭 로직

도보 구간 — 별도 매칭 없이 이동 거리·소요 시간만 요약 표기 (0m 구간은 생략)

버스 구간 매칭

좌표 매칭 반경 150m / 60m 안 정류소 탐색
방향 검증 정류소 순번 nodeord로 진행 방향까지 확인
결과 출력 도착 예정(분) · 남은 정류장 수 표기

지하철 구간 매칭

시간표 조회 요일별(평일/토/일) 고정 시간표에서 다음 열차 계산
방향 검증 ODsay way ↔ 열차 종점역명 비교
결과 출력 다음 열차 시각(HH:MM) · 남은 시간 표기
캐싱 — 노선 정보 24h / 도착 정보 15s
Fallback — 주말 데이터 공백 시 평일 시간표 대체
부분 실패 허용 — 경로 요약은 항상 응답에 포함

4. "현재 위치" 출발지 설정과 디스코드 봇의 한계

시도했지만 막힌 지점

"디스코드 봇은 사용자의 실시간 GPS를 받을 수 없다"

길찾기의 편의성을 높이기 위해 현재 위치를 출발지로 자동 설정하는 기능을 추가하려 했지만, 디스코드 봇이라는 플랫폼 자체가 모바일/PC 사용자의 실시간 위치 좌표를 수신할 수단을 제공하지 않아 매번 정류장명이나 주소를 텍스트로 입력해야 하는 한계가 있었습니다.

5. 해결책 — 디스코드 봇 유지 + 웹 서비스 추가

디스코드 챗봇은 그대로 운영하면서, 별도로 웹 서비스를 추가했습니다. 기존 봇의 API 호출·매칭 로직 코드를 대부분 그대로 재사용하고, 인터페이스만 웹에 맞게 분리했습니다.

백엔드

FastAPI로 전환. 기존 로직 함수를 그대로 두고, /api/* 엔드포인트가 결과를 JSON으로 반환

프론트엔드

HTML, CSS, JS로 구현. 브라우저 Geolocation API로 좌표를 받아 그대로 API에 전달

서버 / 도메인

Oracle Cloud 서버에 배포, DuckDNS로 도메인 발급

인증서

Caddy로 HTTPS 인증서 자동 발급 및 갱신

디스코드 봇 (유지)
  • 현재 GPS 수신 불가 → 정류장명 직접 입력 필요
  • 기존 사용자는 디스코드에서 그대로 이용 가능
웹 서비스 (신규 추가)
  • 클릭 한 번으로 Browser Geolocation GPS 수신 → 출발지 자동 설정
  • 설치 없이 URL 접속만으로 바로 이용

6. 향후 계획 (Roadmap)

웹 전용 UI 개선

봇에서 웹으로 전환하는 과정을 우선했기 때문에, 현재 UI는 아직 웹 환경에 완전히 최적화되지 않음. 웹에 맞는 UI/UX로 개선 예정.

PC 위치 정확도 개선

모바일에서는 현재 위치가 정확히 잡히지만, PC 환경에서는 상대적으로 부정확하게 나오는 문제 확인. 개선 방안 검토 필요.

CRUD 기능 추가

길찾기 기능 및 웹 전환 과정에 예상보다 많은 시간이 소요되어 미뤄졌던 CRUD 기능(시간표 등 데이터 관리)을 추가할 예정.
